Roteiro completo seguindo o roadmap de Computer Science — da linguagem C até System Design. Uma trilha pros iniciantes e uma trilha pra você conduzir como mentor.

§Como usar este plano

São duas trilhas paralelas. A trilha do grupo é a ordem das aulas e exercícios que vocês fazem juntos. A trilha do mentor (você) é como se preparar antes pra ensinar e responder dúvidas — está no fim do documento.

Cada fase tem um checkpoint: o que os amigos devem conseguir fazer sozinhos, sem ajuda, antes de avançar. Se não passam, não avança — repete o exercício, não o vídeo.

A regra de ouro

Vídeo não forma mestre — código forma. A cada estrutura ou conceito novo, cada pessoa reimplementa do zero sem olhar. Assistir passivamente cria uma ilusão de domínio que evapora na primeira tela em branco.

Sobre o prazo, com honestidade

4h por dia por mais de um ano é uma maratona. Consistência vale mais que velocidade. Reservem 1 semana de folga/revisão a cada ~2 meses — descanso planejado evita o abandono por exaustão. As durações abaixo assumem dias de estudo de verdade, não dias corridos de calendário.

Estudo e projeto andam juntos

Vocês não esperam o fim pra construir. A partir da Fase 2 (quando já têm hash table) abrem o capstone — o mini-Redis — e cada fase nova destrava uma camada nova dele. O estudo ensina o conceito; a camada do projeto crava ele. Detalhes na Trilha de projeto.

§O dia de 4 horas

Uma estrutura que funciona pra grupo com mentor. Ajustem, mas mantenham os quatro blocos.

0:20

1:50

2:50

Tipos de dados avançados — fechando o roadmap

Destrava ao longo das Fases 3–6
esforço ~3–4 sem (incremental)

Esta é a camada que faz o projeto cravar os nós do roadmap que sobrariam de fora. Cada comando novo do seu DB é, na prática, uma estrutura ou algoritmo do roadmap em uso real — exatamente como o Redis de verdade faz.

  • Sorted Set (ZADD/ZRANGE) sobre uma Skip List — exercita skip list e ordenação por score.
  • Autocomplete de chaves por prefixo sobre uma Trie / PATRICIA — exercita árvores digitais.
  • KEYS pattern e SCAN MATCH com glob — casamento de padrões: força bruta → KMP / Boyer-Moore; o glob com */? é backtracking.
  • Busca fuzzy (“você quis dizer…”) por distância de edição — Programação Dinâmica em produção.
  • Bitmaps (SETBIT/BITCOUNT) — operadores bit a bit; e a serialização binária do C4 te dá endianness.
  • HyperLogLog e Bloom filter (PFADD/PFCOUNT) — probabilidade, combinatória e hashing aplicados.
  • Geo (GEOADD/GEOSEARCH) sobre uma K-D Tree — busca espacial; e INCRBYFLOAT exercita ponto flutuante.
  • Opcional/ápice: módulo de grafo com menor caminho (Dijkstra/BFS) — fecha a parte de grafos do roadmap dentro do projeto.

Por que isso importa

Quase ninguém consegue dizer “implementei skip list, trie, bloom filter, WAL, replicação e protocolo de rede — tudo no mesmo projeto, em C”. Quando os quatro chegarem ao fim, cada um terá tocado todas as áreas do roadmap com as próprias mãos. Isso é o que separa “fiz um curso” de “sei construir”.

1 · O esqueleto de um programa

Todo programa em C tem a mesma espinha: você inclui bibliotecas, declara a função main (o ponto de partida) e termina cada comando com ponto e vírgula.

#include <stdio.h>      // biblioteca de entrada e saída (printf, scanf)

int main() {            // a execução SEMPRE começa aqui
    printf("Olá!\n");   // cada comando termina com ;
    return 0;           // 0 = "terminou tudo certo"
}

As 4 peças que se repetem sempre

#include traz ferramentas prontas. { } delimitam blocos. ; encerra cada comando (esquecer o ; é o erro nº1 do iniciante). return 0; avisa o sistema que deu tudo certo.

2 · Variáveis e tipos

Uma variável é uma “caixa” com nome que guarda um valor. Em C você precisa dizer o tipo da caixa antes de usar.

int    idade = 25;        // número inteiro
float  altura = 1.75;     // número com vírgula (precisão simples)
double preco = 1999.90;   // número com vírgula (mais preciso)
char   letra = 'A';       // UM caractere — aspas SIMPLES
const double PI = 3.14159; // const = não pode mudar depois

Aspas fazem diferença

'A' (aspas simples) é UM caractere. "A" (aspas duplas) é uma string. Trocar isso é um erro comum.

3 · Entrada e saída — printf e scanf

printf mostra na tela; scanf lê o que o usuário digita. Os “%” são marcadores que dizem o tipo do dado.

int idade;
printf("Quantos anos voce tem? ");
scanf("%d", &idade);              // & = "endereco de" (scanf precisa dele!)
printf("Voce tem %d anos.\n", idade);

// vários de uma vez:
printf("Nome: %s | Idade: %d | Altura: %.2f\n", nome, idade, altura);

O & no scanf e os atalhos

No scanf, variáveis comuns levam & antes (ex.: &idade) — é onde o valor vai ser guardado. Exceção: string (vetor de char) NÃO leva &. Atalhos úteis: \n pula linha, \t dá um tab, %.2f mostra 2 casas decimais.

4 · Operadores

// Aritméticos
a + b   a - b   a * b   a / b   a % b   // % = resto da divisão

// Atribuição (atalhos)
x += 5;   // x = x + 5      x -= 2;   x *= 3;   x /= 2;

// Comparação (resultam em verdadeiro/falso)
a == b   // IGUAL  (atencao: == e nao =)
a != b   // diferente
a > b    a < b    a >= b    a <= b

// Lógicos
a && b   // E   (os dois verdadeiros)
a || b   // OU  (pelo menos um)
!a       // NAO (inverte)

// Incremento / decremento
i++;   // i = i + 1        i--;   // i = i - 1

A pegadinha eterna: = vs ==

= atribui (coloca um valor na variável). == compara. Escrever if (x = 5) sem querer é um bug clássico — sempre dá “verdadeiro” e muda o x. Para comparar, é sempre ==.

Divisão de inteiros engana

7 / 2 dá 3 (não 3.5!), porque os dois são int. Para ter casas decimais, um deles precisa ser float/double: 7.0 / 2 dá 3.5.

5 · Condicionais — if, else, switch

if (idade >= 18) {
    printf("Maior de idade\n");
} else if (idade >= 13) {
    printf("Adolescente\n");
} else {
    printf("Crianca\n");
}

// switch: quando você compara UMA variável com vários valores fixos
switch (opcao) {
    case 1: printf("Um\n");   break;   // break = sai do switch
    case 2: printf("Dois\n"); break;
    default: printf("Invalido\n");     // se nenhum bateu
}

Não esqueça o break

Sem break, o switch “escorrega” e executa os próximos case também. Quase sempre você quer o break em cada caso.

6 · Laços (loops)

Servem pra repetir. while repete enquanto uma condição for verdadeira; for é o mesmo, mas com contador embutido; do-while roda pelo menos uma vez.

// for — quando você sabe quantas vezes (o mais usado)
for (int i = 0; i < 5; i++) {
    printf("%d ", i);     // imprime: 0 1 2 3 4
}

// while — repete enquanto a condição for verdadeira
int n = 10;
while (n > 0) {
    printf("%d ", n);
    n--;                  // CUIDADO: se esquecer isso, loop infinito!
}

// do-while — executa, depois testa (roda no minimo 1 vez)
do {
    printf("Pelo menos uma vez\n");
} while (0);

// break sai do laço; continue pula pra próxima volta
for (int i = 0; i < 10; i++) {
    if (i == 5) break;       // para tudo no 5
    if (i % 2 == 0) continue; // pula os pares
    printf("%d ", i);         // imprime: 1 3
}

Loop infinito

Todo while precisa de algo que aproxime do fim (mudar a variável da condição). Esqueceu o n--? O programa trava repetindo pra sempre. É a pegadinha mais comum de laço.

7 · Vetores (arrays)

Um vetor guarda vários valores do mesmo tipo numa fila. O índice começa em 0 — sempre.

int notas[5] = {7, 8, 9, 10, 6};   // 5 posições: índices 0 a 4
printf("%d\n", notas[0]);          // 7  (a PRIMEIRA é o índice 0)
notas[2] = 5;                      // muda a terceira posição

// percorrer com for:
int soma = 0;
for (int i = 0; i < 5; i++) {
    soma += notas[i];
}

Estourar o vetor não dá erro… na hora

Um int v[5] vai de v[0] a v[4]. Acessar v[5] é “fora dos limites” — C deixa, mas você lê/escreve numa memória que não é sua. Vira bug bizarro ou crash. Sempre respeite 0 até tamanho-1.

8 · Matrizes (vetores 2D)

Uma matriz é um vetor de vetores — tipo uma tabela com linhas e colunas.

int tabela[2][3] = {
    {1, 2, 3},    // linha 0
    {4, 5, 6}     // linha 1
};
printf("%d\n", tabela[1][2]);   // 6  (linha 1, coluna 2)

// percorrer: um for dentro do outro
for (int i = 0; i < 2; i++) {       // linhas
    for (int j = 0; j < 3; j++) {   // colunas
        printf("%d ", tabela[i][j]);
    }
    printf("\n");
}

9 · Structs (registros)

Uma struct junta vários campos relacionados num só “tipo” seu. Perfeito pra representar coisas do mundo real (um lead, um cliente, um ponto…).

struct Lead {
    char  nome[50];
    int   idade;
    double valor;
};

struct Lead l1;                 // cria um
strcpy(l1.nome, "Caio");        // acessa campo com ponto (.)
l1.idade = 25;
l1.valor = 1999.90;
printf("%s tem %d anos\n", l1.nome, l1.idade);

Liga com o trabalho

Struct é a base do que você já faz em C# com classes/DTOs. Aqui é a versão crua: um agrupamento de dados. No projeto capstone, cada entrada do banco vai ser, no fundo, uma struct.

10 · Funções e procedimentos

Função é um bloco de código com nome, que você chama quando quiser. Evita repetir e organiza tudo. Tem tipo de retorno, nome e parâmetros.

// função que RETORNA um valor
int somar(int a, int b) {
    return a + b;
}

// "procedimento": não retorna nada -> void
void saudar(char nome[]) {
    printf("Ola, %s!\n", nome);
}

int main() {
    int r = somar(3, 4);   // r = 7
    saudar("Caio");
    return 0;
}

Passagem por valor

Por padrão, C passa uma cópia do argumento. Mudar o parâmetro dentro da função não muda a variável original lá fora. Pra mudar de verdade, você usa ponteiros (próximo tópico). Esse é o link direto pra Fase 1.

Protótipo

Se a função aparece depois do main, declare o protótipo no topo: int somar(int, int); — é só avisar ao compilador que ela existe.

11 · Ponteiros — o muro mais alto

Esse é o conceito que mais trava iniciante, então vai devagar. Toda variável mora num endereço na memória (tipo o número de uma casa). Um ponteiro é uma variável que guarda um endereço — ou seja, “aponta” pra onde outra variável mora.

A analogia da casa

Endereço = o número da casa.   &x = “me dá o endereço da casa do x”.   *p = “abre a casa que o p aponta e me mostra o que tem dentro”.

int x = 10;
int *p = &x;     // p guarda o ENDEREÇO de x  (& = "endereço de")

printf("%d\n", x);    // 10  -> o valor
printf("%p\n", p);    // 0x...  -> o endereço (a "casa")
printf("%d\n", *p);   // 10  -> o valor NA casa que p aponta (* = "conteúdo de")

*p = 20;         // muda o conteúdo da casa -> muda o PRÓPRIO x!
printf("%d\n", x);    // 20

Agora o passo que faltava nas funções: passar o endereço pra função poder alterar a variável original.

void dobrar(int *n) {     // recebe um ponteiro
    *n = *n * 2;          // altera o conteúdo lá na origem
}

int main() {
    int valor = 5;
    dobrar(&valor);       // passa o ENDEREÇO de valor
    printf("%d\n", valor); // 10  -> mudou de verdade!
}

Resumo dos dois símbolos

& pega o endereço de uma variável. * (na hora de usar) abre o ponteiro e mexe no valor que ele aponta. Decore: “& = onde mora, * = o que tem dentro”.

12 · Alocação dinâmica de memória

Até aqui o tamanho de tudo era fixo (int v[5]). Mas e quando você só descobre o tamanho durante a execução (ex.: o usuário diz quantos itens)? Aí você pede memória na hora com malloc — e depois devolve com free.

#include <stdlib.h>     // malloc, free

int n;
printf("Quantos numeros? ");
scanf("%d", &n);

// pede memória pra n inteiros (na "heap")
int *v = malloc(n * sizeof(int));
if (v == NULL) { return 1; }   // sempre cheque se deu certo

for (int i = 0; i < n; i++) v[i] = i * 10;

free(v);     // DEVOLVE a memória. Esquecer = vazamento (memory leak)
v = NULL;    // boa prática: evita usar um ponteiro "morto"

A regra de ouro da memória

Todo malloc precisa de um free correspondente. Esqueceu o free? O programa vai comendo memória (leak). Usou depois do free? Bug grave (use-after-free). Esse cuidado é exatamente o que a Camada C2 do projeto vai cobrar de vocês.

Por que isso é o pré-requisito de tudo

Listas, árvores, hash tables — toda estrutura de dados “cresce” em tempo de execução, e isso só é possível com ponteiros + alocação dinâmica. É por isso que o plano insiste: não pulem ponteiros e memória. Sem isso, a Fase 2 em diante não anda.

13 · Projeto com vários arquivos

Programas reais não vivem num arquivo só. Você separa em .h (o que existe — as “assinaturas”) e .c (como funciona — o código).

// ---------- matematica.h ----------
#ifndef MATEMATICA_H      // include guard: evita incluir 2x
#define MATEMATICA_H
int somar(int a, int b);  // só a assinatura (protótipo)
#endif

// ---------- matematica.c ----------
#include "matematica.h"
int somar(int a, int b) { return a + b; }   // a implementação

// ---------- main.c ----------
#include <stdio.h>
#include "matematica.h"   // aspas " " = arquivo seu (< > = do sistema)
int main() { printf("%d\n", somar(2, 3)); return 0; }

Include guard

O trio #ifndef / #define / #endif garante que o cabeçalho seja incluído uma única vez, mesmo se vários arquivos o pedirem. Sem ele, dá erro de “redefinição”.

14 · Conversão de tipos (casting) e sizeof

Às vezes você precisa forçar um tipo a virar outro. E sizeof diz quantos bytes algo ocupa.

int a = 7, b = 2;
double r = (double)a / b;     // 3.5 — o (double) força a conta a virar decimal
printf("%zu\n", sizeof(int)); // 4 (em geral) — tamanho do tipo em bytes

15 · Operador ternário

Um if/else enxuto, em uma linha. Formato: condição ? valor_se_verdadeiro : valor_se_falso.

int idade = 20;
char *tipo = (idade >= 18) ? "adulto" : "menor";   // escolhe na hora
int maior = (a > b) ? a : b;                        // máximo entre dois

16 · Escopo, static e const

Variável declarada dentro de uma função (local) só existe ali. Global (fora de tudo) existe no programa inteiro. static faz uma local lembrar o valor entre chamadas. const trava o valor.

int contador() {
    static int n = 0;   // não zera a cada chamada — lembra o valor
    return ++n;         // 1, 2, 3, ... a cada vez que chamar
}
const double TAXA = 0.05;   // não pode ser alterado depois

17 · Recursão

Uma função que chama a si mesma. Precisa SEMPRE de um caso base (a condição de parada), senão vira loop infinito que estoura a memória (stack overflow).

int fatorial(int n) {
    if (n <= 1) return 1;          // caso base: para aqui
    return n * fatorial(n - 1);    // chama a si mesma, menor
}
// fatorial(4) = 4*3*2*1 = 24

Por que importa

Recursão é o jeito natural de percorrer árvores e resolver “dividir pra conquistar” (Merge Sort, Quick Sort). É um músculo que você vai usar muito da Fase 3 em diante.

18 · enum, typedef e union

enum Status { ATIVO, INATIVO, PENDENTE };   // vira 0, 1, 2 — nomes pra inteiros
enum Status s = ATIVO;

typedef struct {                            // typedef = apelido de tipo
    char nome[50];
    int  idade;
} Pessoa;
Pessoa p;        // agora não precisa escrever "struct" toda hora

union Valor {    // union: todos os campos dividem o MESMO espaço
    int   inteiro;
    float decimal;
};               // útil pra economizar memória quando só um é usado por vez

19 · Pré-processador e macros (#define)

O #define faz uma “troca de texto” antes de compilar. Serve pra constantes e pequenas macros.

#define PI 3.14159
#define AREA(r) (PI * (r) * (r))    // macro com argumento

double a = AREA(5);   // o compilador troca por (3.14159 * (5) * (5))

⚠ Parênteses são obrigatórios

Em macro, embrulhe cada argumento em parênteses: (r). Sem isso, AREA(2+1) vira conta errada. Macro não é função — é substituição literal de texto.

20 · Operadores bit a bit

Mexem nos bits diretamente. Parecem exóticos agora, mas são a base de bitmaps, flags e compressão.

a & b    // AND  — 1 só onde os dois são 1
a | b    // OR   — 1 onde pelo menos um é 1
a ^ b    // XOR  — 1 onde são diferentes
~a       // NOT  — inverte todos os bits
a << 2   // desloca p/ esquerda  (= multiplica por 4)
a >> 1   // desloca p/ direita    (= divide por 2)

21 · Ponteiro de função

Dá pra guardar uma função dentro de uma variável e chamá-la depois. Parece estranho, mas é o coração de como C faz “polimorfismo” e tabelas de comando.

int somar(int a, int b) { return a + b; }

int (*op)(int, int) = somar;   // op aponta para a função somar
printf("%d\n", op(2, 3));      // 5 — chama através do ponteiro

22 · Arquivos — ler e escrever em disco

Até aqui tudo morria quando o programa fechava. Com arquivos, os dados persistem.

#include <stdio.h>

FILE *f = fopen("dados.txt", "w");   // "w" escreve, "r" lê, "a" anexa
if (f != NULL) {

f = fopen("dados.txt", "r");
if (f) { fgets(linha, sizeof linha, f); fclose(f); }

Strings em C — o caderno

Tudo o que vocês precisam sobre strings: o conceito, os comandos, as funções e as pegadinhas. Cole no caderno, deixe aberto enquanto codam.

A ideia que explica tudo: o \0

Em C não existe um tipo “string”. Uma string é só um vetor de char que termina num caractere especial: o \0 (byte zero, “null terminator”). Toda função de string para de trabalhar quando encontra o \0. Entendeu isso, entendeu 90% dos bugs.

1 · Declaração e inicialização

char a[] = "C";          // tamanho 2: 'C' + '\0' (o compilador conta)
char b[20] = "Plaenge";  // reserva 20, usa 8, sobra espaço pra crescer
char c[4] = "abc";       // OK: a,b,c,\0 — exatamente 4
char d[3] = "abc";       // BUG: não cabe o '\0'!
char *e = "texto";       // ponteiro p/ string LITERAL (não pode alterar)

Vetor char[] vs ponteiro char*

char s[] = "oi" cria uma cópia que você pode alterar. char *s = "oi" aponta pra um literal somente-leitura — tentar mudar trava o programa. Pra texto que muda, use vetor.

2 · Acentos no console — setlocale

É o que aparece no topo do código da sua aula. Sem isso, ç, ã e á saem quebrados no terminal do Windows.

#include <locale.h>
setlocale(LC_ALL, "Portuguese");   // habilita acentuação

3 · Entrada — lendo strings

scanf("%s", s)stdio.h

Lê uma palavra (para no primeiro espaço). Repare: com vetor de char não se usa &.

char nome[30];
scanf("%s", nome);   // digita "João Silva" -> guarda só "João"
fgets(s, n, stdin)stdio.h

Lê uma linha inteira com segurança (limita o tamanho). É o jeito recomendado. Inclui o \n no fim — às vezes você quer remover.

char linha[100];
fgets(linha, sizeof linha, stdin);
linha[strcspn(linha, "\n")] = '\0';   // tira o \n do fim
gets(s) ❌ PROIBIDOstdio.h

O Pietro mostra, mas é pra você nunca usar. Não limita o tamanho → estoura o buffer → falha de segurança clássica. Foi removido do C11. Use sempre fgets no lugar.

char s[10];
gets(s);   // se o usuário digitar 50 chars, corrompe a memória

4 · Saída — imprimindo strings

puts(s)stdio.h

Imprime a string e já pula linha (adiciona \n sozinho). Mais simples que printf quando é só texto puro.

puts("Antes do strcat:");   // imprime e quebra a linha
saídaAntes do strcat:
printf("%s", s)stdio.h

Imprime com formatação. Use quando precisa misturar texto e variáveis.

printf("str1: %s\n", s1);   // %s = encaixa a string aqui
putchar(c)stdio.h

Imprime um único caractere. Útil ao percorrer a string letra a letra.

putchar('A');   // imprime: A

5 · Percorrer caractere a caractere

O padrão mais importante: ande pelo vetor até bater no \0.

char s[] = "C é vida";
for (int i = 0; s[i] != '\0'; i++) {   // para no terminador
    putchar(s[i]);
}

6 · Biblioteca string.h — as funções

strlen(s)string.h

Tamanho lógico da string — conta até o \0, sem incluí-lo. Diferente de sizeof, que é o tamanho do vetor.

char s[] = "Plaenge";
size_t n = strlen(s);   // 7  (P-l-a-e-n-g-e)
sizeof s;               // 8  (7 letras + o '\0')
saídan = 7 | sizeof = 8

Procura uma substring dentro de outra. Retorna ponteiro pro início (ou NULL). É o irmão de alto nível do KMP/Boyer-Moore que vocês veem na Fase 6.

10 · Pegadinhas clássicas (decore estas)

  1. Esquecer o espaço do \0: "abc" precisa de char[4], não char[3].
  2. Comparar com == (compara endereços!). Use strcmp.
  3. Copiar com = (s1 = s2 não copia o conteúdo). Use strcpy.
  4. strcat/strcpy sem espaço no destino → buffer overflow (corrompe memória).
  5. gets() → nunca. Use fgets.
  6. Misturar scanf("%d") e fgets → sobra um \n no buffer. Padronize em fgets.
  7. strncpy pode não pôr o \0 — coloque você mesmo.
  8. strtok destrói a string original e não é thread-safe (strtok_r).
  9. Usar string não inicializada (lixo de memória, sem \0) → leitura infinita.
  10. Confundir strlen (tamanho do texto) com sizeof (tamanho do vetor).

3 · Artigos — a, an, the

  1. a = um/uma, antes de som de consoante: a car, a book, a university (“iu”, som de consoante).
  2. an = um/uma, antes de som de vogal: an apple, an hour (o “h” é mudo).
  3. the = o/a/os/as, quando é algo específico: the car I bought (o carro que comprei).

4 · Plural dos substantivos

  1. Regra geral: +s → car → cars, book → books.
  2. Depois de s, x, ch, sh: +es → box → boxes, watch → watches.
  3. Termina em consoante + y: y → ies → city → cities, baby → babies.
  4. Irregulares (decore): man → men, woman → women, child → children, person → people, foot → feet.

⚠ people é plural

“People” já é o plural de “person”. Então é people are, nunca “people is”. E não existe “peoples” no sentido de pessoas.

5 · Present Simple — rotinas e fatos

Usa pra hábitos, rotinas e verdades (“eu trabalho”, “ela mora”, “a água ferve a 100°”). É o tempo mais usado.

A regra do -s na 3ª pessoa

Com he / she / it, o verbo ganha -s: He works, She lives. Esquecer esse “s” é o erro mais comum de todos — fique atento.

15 · Present Perfect — o passado que toca o presente

Esse é o tempo que mais confunde brasileiro, porque não tem tradução exata. Fórmula: have/has + particípio (a 3ª forma do verbo). Liga uma ação do passado ao agora — sem dizer quando exatamente.

I have finished the report.
Eu terminei o relatório. (e está pronto agora)
She has lived here for ten years.
Ela mora aqui há dez anos. (e ainda mora)
Have you ever traveled abroad?
Você já viajou pro exterior? (experiência de vida)

for vs since

for = um período (for two years = por dois anos). since = o ponto de início (since 2020 = desde 2020). Companheiros úteis: already (já), yet (ainda — em negativas/perguntas), just (acabou de).

⚠ Present Perfect vs Past Simple

Use Past Simple quando diz quando (I ate at 8pm). Use Present Perfect quando o tempo é indefinido e o resultado importa agora (I have eaten = já comi, não estou com fome).

16 · Present Perfect Continuous — duração que continua

Fórmula: have/has been + verbo-ing. Enfatiza quanto tempo algo vem acontecendo (e geralmente ainda acontece).

I have been studying for three hours.
Estou estudando há três horas.
It has been raining all day.
Está chovendo o dia todo.

17 · Past Continuous — o que estava rolando

Fórmula: was/were + verbo-ing. Ação em andamento no passado, geralmente interrompida por outra (no Past Simple).

I was sleeping when the phone rang.
Eu estava dormindo quando o telefone tocou.
They were working while I was cooking.
Eles estavam trabalhando enquanto eu cozinhava.

18 · Past Perfect — o passado do passado

Fórmula: had + particípio. Marca algo que aconteceu antes de outro momento no passado.

When I arrived, the movie had already started.
Quando cheguei, o filme já tinha começado.
She had never seen snow before that trip.
Ela nunca tinha visto neve antes daquela viagem.

19 · Comparativos e superlativos

  1. Adjetivos curtos (+er / +est): cheap → cheaper → the cheapest.
  2. Adjetivos longos (more / most): expensive → more expensive → the most expensive.
  3. Irregulares: good → better → best · bad → worse → worst · far → farther/further.
  4. Igualdade (as … as): tão … quanto.

21 · Gerúndio (-ing) vs Infinitivo (to)

Depois de certos verbos vem -ing; depois de outros, to + verbo. Não tem regra mágica — os principais se decoram com o uso.

  1. + -ing: like, love, enjoy, hate, finish, avoid, e depois de qualquer preposição.
  2. + to: want, need, decide, hope, would like, learn.

23 · Advérbios e frequência

Advérbio diz como algo acontece. Formação comum: adjetivo + -ly (quick → quickly). Irregulares: good → well, fast → fast.

Quando o foco vai pra quem sofre a ação, não pra quem faz. Fórmula: be (no tempo certo) + particípio.

29 · Wish / If only — desejos e arrependimentos

30 · Modais avançados — dedução e “modal perfect”

  1. Dedução: must be (deve ser — quase certeza), can't be (não pode ser), might/could be (talvez).
  2. Modal + have + particípio (sobre o passado): should have done (deveria ter feito), must have done (deve ter feito), could have done (poderia ter feito).

31 · Phrasal verbs — como funcionam

São verbo + partícula (preposição/advérbio) que, juntos, mudam o sentido. look = olhar, mas look for = procurar, look after = cuidar de. Não dá pra traduzir ao pé da letra — aprende-se pelo uso.

Alguns do dia a dia: get up (levantar), give up (desistir), find out (descobrir), turn on/off (ligar/desligar), come back (voltar), look for (procurar).

Separáveis

Muitos aceitam o objeto no meio: turn the light off = turn off the light. Com pronome, é obrigatório no meio: turn it off (nunca “turn off it”).

A real sobre “ser craque”

Ninguém vira elite vendo mais vídeo. Vira construindo coisas difíceis, lendo código dos grandes e indo fundo num assunto. O capstone de vocês já é metade disso. O resto é profundidade e gosto por entender o “por quê” embaixo de cada camada.

1 · Algoritmos de elite

  • Programação dinâmica avançada (DP em árvore, bitmask, em intervalos) e fluxo máximo (Dinic, min-cost-max-flow).
  • Algoritmos de string de verdade: Suffix Array/Automaton, Aho-Corasick, Z-function.
  • Geometria computacional (convex hull, sweep line).
  • Treino: Codeforces / competitive programming — é academia pesada pra raciocínio algorítmico.

2 · Matemática de verdade

É o que destrava ML, criptografia e análise séria de algoritmos: matemática discreta (lógica, combinatória, grafos), álgebra linear (base de toda IA), teoria dos números (criptografia) e probabilidade.

3 · Sistemas a fundo

  • Como um compilador funciona (lexer, parser, geração de código) — escreva um pequeno.
  • Internals de SO: escreva um “toy kernel” ou um shell; entenda paginação e escalonamento por dentro.
  • Internals de banco: B+Tree, LSM-Tree, MVCC, WAL — exatamente o que o capstone toca.
  • Sistemas distribuídos: consenso (Raft, Paxos), CAP/PACELC na prática, relógios lógicos.

4 · Performance e concorrência (mechanical sympathy)

  • Programação cache-aware, SIMD/vetorização, profiling com perf.
  • Concorrência avançada: estruturas lock-free, atomics, memory ordering, event loop (epoll/io_uring).

5 · Qualidade e meta-habilidades

  • Testes property-based, fuzzing, e uma pitada de métodos formais (TLA+).
  • Ler papers (o do Raft, o do Dynamo, o do MapReduce) e ler código de projetos grandes (Redis, SQLite, Linux).
  • Contribuir pra open source e escrever/ensinar — ensinar é o teste final de domínio.

Livros que valem a estante (recomendação, não cópia)

Designing Data-Intensive Applications (Kleppmann) · Computer Systems: A Programmer's Perspective (Bryant & O'Hallaron) · The Algorithm Design Manual (Skiena) · Operating Systems: Three Easy Pieces (grátis online). São os clássicos que aparecem na estante de quase todo engenheiro sênior.

Como levar o capstone ao nível elite

Quando o banco de dados de vocês estiver pronto, estes “stretch goals” o colocam em outro patamar — e rendem os melhores posts de todos: (1) consenso com Raft (réplicas que concordam mesmo com falha); (2) storage em LSM-Tree (como o RocksDB); (3) rede com io_uring/epoll (milhares de conexões); (4) hash table lock-free; (5) fuzzing do parser do protocolo. Cada um destes é assunto de entrevista de empresa top.

§Sua trilha de mentor

Sua preparação é diferente da deles — você já é avançado.

  • Veja sempre um módulo na frente, em 1.5x–2x. Você não está aprendendo o conteúdo; está caçando como o professor explica.
  • Colete analogias. Tenha 2–3 formas de explicar cada conceito difícil. Eles vão perguntar a mesma coisa de cinco jeitos.
  • Sobre-prepare ponteiros e memória. É o muro onde a maioria trava. Tenha pronto: endereço = "número da casa", * = "abrir a casa", & = "pegar o endereço".
  • Reimplemente cada estrutura antes de ensinar, pra codar ao vivo sem gaguejar.
  • Na Fase 4 (Mario), estude de verdade, não em 2x. As provas e análises fecham aquele gap de confundir posição física no array com rank lógico ordenado.
  • Ensinar é o seu teste de maestria. Se não consegue explicar simples, não dominou. Ensinar consolida mais que qualquer revisão.
